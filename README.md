# X-Follow Assistant Pro (Chrome Extension)

## 1. 项目简介 | Introduction
**X-Follow Assistant Pro** 是一款基于 Chrome Manifest V3 标准开发的自动化关注工具，专为 Twitter (X.com) 深度运营设计。

它专注于在**帖子详情页 (Post/Status Page)** 自动扫描评论区用户，通过模拟真实人类的交互行为（悬停、等待卡片、点击）来执行关注操作。项目采用了 **Google 级工程标准**，包含完备的防封控启发式算法 (Heuristics)、双层日志系统以及鲁棒的错误边界处理。

---

## 2. 核心功能 | Core Features

### 🛡️ 防封控机制 (Anti-Ban System)
- **拟人化抖动 (Humanizer Jitter)**: 关注间隔不再是固定值，而是在用户设定的区间（如 3-8秒）内遵循随机分布。
- **批次休息 (Batch & Rest)**: 支持设定“每关注 X 人，强制休息 Y 分钟”，打破机器人的连续操作特征。
- **微交互模拟**: 在点击前会有随机的微小停顿 (200-500ms)，模拟人类反应时间。

### 🧠 智能引擎 (Engine V2)
- **双模式扫描 (Hybrid Scanning)**:
  - **Direct Mode**: 针对点赞/转发列表（直接存在按钮）的场景。
  - **Hover Mode (新增)**: 针对评论区回复，自动执行 **"悬停 -> 等待资料卡 -> 扫描卡片 -> 点击关注"** 的复杂交互链条。
- **URL 守卫**: 自动检测当前页面是否为帖子详情页 (`/status/`)，防止在错误的页面运行。
- **蓝标过滤**: 可选仅关注认证用户 (Verified/Blue Tick)。

### 📊 监控与日志
- **UI 仪表盘**: "暗夜极光" (Dark Aurora) 风格界面，实时显示统计数据。
- **持久化日志**: 最近 50 条操作日志自动保存到 `chrome.storage`，重启浏览器不丢失。
- **全局错误捕获**: 核心循环包裹 `try-catch` 边界，防止因页面结构变更导致脚本崩溃。

## 3. 技术架构 | Technical Architecture

项目采用原生 ES Modules (无构建工具依赖) 以确保极简与高性能。

```text
/
├── manifest.json            # V3 清单配置
└── src/
    ├── popup/               # 用户界面
    │   ├── index.html       # 结构
    │   ├── style.css        # 样式 (Glassmorphism)
    │   └── main.js          # UI 逻辑与配置持久化
    │
    └── content/             # 注入脚本 (核心逻辑)
        └── content.js       # OOP 设计
```

### 核心类设计 (`src/content/content.js`)
1.  **`Engine`**: 中央调度器。负责状态管理、批次计数、URL 校验。
2.  **`DOMScanner`**: 负责解析 DOM。兼容 `[data-testid="tweet"]` (回复) 和 `[data-testid="UserCell"]` (列表) 两种结构。
3.  **`HoverCardController`**: **(核心)** 处理复杂的悬停交互。
    - 触发 `mouseover` 事件。
    - 轮询等待 `[data-testid="HoverCard"]` 出现。
    - 在卡片内查找关注按钮并执行点击。
    - 触发 `mouseout` 清理现场。
4.  **`Humanizer`**: 提供 `randomDelay` 和 `tinyPause` 等工具函数。
5.  **`Logger`**: 双向日志系统 (Console + Runtime Message + Storage)。

## 4. 安装与使用 | Installation & Usage

### 安装步骤
1.  下载本项目源代码。
2.  打开 Chrome 浏览器，访问 `chrome://extensions/`。
3.  开启右上角的 **"开发者模式" (Developer mode)**。
4.  点击 **"加载已解压的扩展程序" (Load unpacked)**。
5.  选择项目根目录。

### 操作指南
1.  打开任意 X (Twitter) 帖子详情页 (例如: `https://x.com/username/status/12345...`)。
2.  点击浏览器右上角的 **X-Follow** 扩展图标。
3.  在面板中配置参数：
    - **Interval**: 建议设置 5-10 秒 (过快易触发验证码)。
    - **Batch Size**: 建议 20-30 人。
    - **Rest Time**: 建议 5-10 分钟。
4.  点击 **"START ENGINE"**。
5.  观察下方的日志终端，查看实时运行情况。

## 6. 用户主页手动采集（v1.1.0）

保留关注、取关和运行记录功能。新增「采集数据」页签，独立于关注引擎运行。默认不采集，需要点击「开始采集」。

### 使用

1. 在 Chrome 111+ 的 `chrome://extensions/` 重新加载本扩展，然后刷新已经打开的 X 页面。
2. 打开用户主页 `https://x.com/用户名`（帖子）或 `https://x.com/用户名/with_replies`（回复）。
3. 点击扩展 →「采集数据」→「开始采集」，采集与滚动独立控制，可手动滚动或点击「开始滚动」。扩展仅在采集期间监听页面自身发出的 `UserTweets` / `UserOriginalsTimeline` / `UserTweetsAndReplies` / `UserRepliesTimeline` GraphQL 请求（fetch / XMLHttpRequest），每次成功响应后自动合并到本地；由页面滚动触发加载，不直接调用时间线接口或点击关注。
4. 点击「停止采集」结束；关闭扩展面板不会停止。同一用户切换帖子和回复不会停止，并分别保存。刷新同一用户页面保持采集，可用于补采首屏；切换其他用户或离开帖子/回复页面会停止，需重新点击开始。
5. 在「采集数据」查看各用户、各 Tab 的条数、首次及最近采集时间。每个分类可单独「清空」或导出 JSON。清空会停止该用户的采集会话并保留其他分类的数据；清空后旧响应不会重新写回。

「开始」只记录之后触发的新请求，不补采开始前已加载的内容；可自动或手动向下滚动加载。再次开始会合并到已有分类，而不是清空已有数据。

导出命名：`用户名_用户ID_posts或replies_YYYYMMDD_HHmmss.json`，例如 `alice_123456_posts_20261019_183000.json`。文件名时间使用电脑本地时间；JSON 时间采用 UTC ISO 8601。每次导出一个用户的一个 Tab，帖子和回复可分别下载。

### 数据规则

- 使用稳定的用户 ID + Tab 分类，同一用户改名后仍进入同一分类，不同用户不会因用户名相同而合并。
- 每个分类按推文 ID 去重；重复采集保留首次时间，更新最新内容及互动数据。较旧响应不会覆盖较新的记录；最新响应缺失的计数为 `null`。
- 每条内容包含 `id`、`url`、`author`、`text`、`publishedAt`、`firstCapturedAt`、`lastCapturedAt`、`metrics`（likes/replies/reposts/quotes/views/bookmarks）、`relationships`、`media`、`source`、原始推文 `raw` 和原始时间线 item 包装 `rawItem`。
- 集合的 `owner` 是当前主页用户，`author` 是内容实际作者。回复线程中的上下文、主页中的转发不会被伪装为该用户原创；引用或转发的嵌套原文保留在 raw 中，不展开成额外记录。广告、游标不算推文。
- 记录接口实际返回的内容，并非完整账号归档；页面缓存若未再次发出请求，不会产生新的采集。开始前已加载的内容可通过开启采集后刷新同一用户页面重新获取。
- 支持上述用户时间线接口（含新版帖子接口 UserOriginalsTimeline 和回复接口 UserRepliesTimeline）。X 改动接口名称或响应结构时可能需要更新解析器；若有 GraphQL 错误，无法读取的数据不计为成功。保存失败在采集面板显示。

运行中的采集会话使用 `chrome.storage.session`，浏览器重启后失效。数据使用独立的 `capture:*` 存储键，与关注设置、运行历史互不影响。为保留较多原始 item，使用 `unlimitedStorage` 权限；数据仍占用本机磁盘，不自动淘汰。卸载扩展会移除扩展本地数据，请及时导出备份。扩展不保存请求头、Cookie 或认证令牌，不向外部服务上传采集结果。

## 取关助手的两种模式

在「取关助手」选择「仅标记」或「自动取关」，再启动。默认仅标记，旧配置也默认仅标记；运行时不能切换，先停止再选择另一模式。

- 仅标记：在正在关注列表中，对未显示「关注了你」标识的用户添加「疑似未回关」标签，不点击取关或确认按钮。统计和运行记录显示标记数量。
- 自动取关：保留原来的自动取消关注流程，需主动选择。

两种模式均跳过显示回关标识的用户。未显示标识不代表一定没有回关，页面加载和结构变化可能影响判断。

### 自动向下滚动

采集与滚动是两组独立按钮，默认均关闭：

- 开始采集：只开启记录，可手动浏览、切换同一用户的帖子/回复。
- 开始滚动：每 2.5 秒向下滚动约八成屏幕，不改变采集状态。
- 停止滚动：仅停止页面移动，正在进行的采集继续。
- 停止采集：仅停止记录，不改变滚动状态。

关闭面板后两者维持各自状态；同一用户切换帖子/回复保持状态。切换其他用户或离开支持页面会停止。刷新同一用户页面继续采集，但滚动停止。到底后滚动继续等待，但不会凭空产生新数据；浏览器后台节流或电脑休眠可能延迟滚动。点击开始前已经加载的内容，可在开启采集后刷新页面补采。


### 操作录制（流程分析第一步）

重新加载扩展并刷新 X 页面后，打开「操作录制」页签，点击「开始录制」。关闭面板，照平时的方式打开帖子、点击回复、输入和滚动；页面左下角会显示录制提示。完成后回到插件，点击「停止录制」和「导出操作日志 JSON」。把文件用于分析操作顺序。

录制仅作用于开始时的 X 标签页，页面刷新及 X 内跳转后继续，关闭面板不影响。它与时间线采集和自动滚动独立。记录操作时间、页面路径、点击元素的标签/角色/test ID、关联帖子 ID/链接、滚动位置、输入动作及弹窗开关；不记录输入文字、密码、Cookie、认证信息和鼠标移动轨迹。链接去除查询参数和锚点，控件名称最多 120 字。当前步骤不读取整篇帖子正文，也不生成或发布回复。

日志保存在浏览器本地；再次开始会追加，只有点击清空才删除。最多 5000 条，达到上限自动停止，先导出再清空即可继续。刷新延续录制，浏览器重启后需重新开始。日志末尾可在面板预览，导出包含全部已保存事件。


### 可配置回复测试（本地回复池）

重新加载扩展并刷新 X 页面后，在「操作录制」页设置本次回复数量（1–50）和间隔最小/最大秒数（0–3600），点击「按设置开始（会发布）」。默认 3 条、10–20 秒。最小值不能大于最大值，相等表示固定等待；设置会保存在本地。保留快捷「测试一条」「测试三条」，使用同一组间隔设置。运行中设置锁定，修改只适用于下一次测试。

多条测试从首页开始，依次选择未处理的普通文字帖；数量为 1 时也支持已打开的详情页。广告、当前账号自己的帖子和回复、已提交过的目标都会排除，识别不了账号或账号变化时停止；既有草稿不会覆盖。回复从内置 300 条约 20–40 字、带关注或主页访问邀请的回复中随机抽取，同批不重复，不承诺回关，不调用真实生成服务。已确认的自身回复 ID 保存在本地，防止回流首页后再被选中。

每一条按以下顺序执行：进入详情并确认正文、回复框就绪 → 随机等待 5–10 秒 → 填入并校验文本 → 再随机等待 5–10 秒 → 点击一次回复并确认新回复 → 在所设区间随机等待 → 返回首页。未达到数量则选择下一条，末条也返回首页。可见目标耗尽时会有限次向下滚动加载；仍无新目标则停止并说明。这里的“间隔”是发布确认后的额外等待，页面加载与阅读停顿另计，实际相邻发布间隔可能更长。

面板显示进度和倒计时。「停止测试」会中断等待并停止后续操作，不撤回已发布回复。429、页面切换、发布失败或结果不明确会停止整批，不自动重试。刷新或关闭测试页面会中断；关闭插件面板不影响运行。诊断包记录整批设置、每条实际抽到的等待时长、结果及各阶段快照。

### 回复测试诊断包

每次点击回复测试时自动开始记录，结束或失败后在「操作录制」页点击「导出完整测试诊断包」。文件按本次 runId 关联，包含步骤/时间/是否点击、错误堆栈、定位选择器和匹配数量，以及各阶段页面实时 DOM 快照。失败时快照扩大到 body。快照附带输入框、按钮的可见性、禁用状态、焦点、位置与遮挡信息，按数量限制快照数（每条预算 30 份，另留 8 份），HTML 总预算约 600 万字符，失败现场优先保留；单份普通快照按数量分配，最多 8 万字符；错误现场最多 16 万字符，截断时会标明。这里只保留清理后的实时 HTML，不保存网页脚本、认证属性或输入文字。

诊断仅观察本次测试期间页面已有的 HomeTimeline/HomeLatestTimeline/TweetDetail/CreateTweet 请求，保存接口名称、方法、状态码和耗时，不保存请求头、请求体、响应体或 URL 查询参数，不额外发送网络请求。发布点击后最多延续 1.5 秒以收集末尾请求；观察期间由运行心跳续期，结束后停止，页面中断且失去心跳 90 秒后自动过期，记录数量有上限。请求日志用于排查，不单独作为发布成功的判断依据。导出保留最近一次测试；下一次测试会替换预览和诊断，请在重试前先导出问题现场。


选帖诊断会记录当前账号、各候选帖的作者及排除原因（`own_author` / `own_reply` / `already_processed`），生成回复时记录回复池编号和池大小。确认发布的回复会保存 ID、当前账号、父帖 ID 和本次 runId，用于后续排除。直接在自己的帖子详情页测试时会停止，不会发布。单条首页测试会跳过自己的内容再选其他目标。
